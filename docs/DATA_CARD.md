# Data card

## Dataset purpose

SmartPick-VLA data supports language-conditioned tabletop sorting, imitation
learning, action-chunk prediction, simulation evaluation, and real-log replay.
It is not a dataset for industrial defect inspection and does not establish the
accuracy of accepted/scratch/unknown labels on real manufactured parts.

## Data sources

### Simulated demonstrations

MuJoCo episodes are generated by the privileged waypoint/IK expert. The current
compressed NPZ stores aligned RGB observations, language instructions, raw
robot-state vectors, normalized continuous actions, episode/step IDs, task
class, and episode-success labels. Its adjacent manifest stores per-episode
seed, instruction template, success, length, return, collision/wrong-action
summary, and sampled domain parameters. It does not retain per-step reward or
termination flags, so analyses requiring those fields need an extended,
versioned format. The generator records every attempted episode even when a
training dataset later selects successful transitions only.

### Real logs

Compatible JSONL logs may be imported from an external robot system. A real log
retains `source=real`; simulation output produced by replay uses
`source=real_replay` and refers back to the source episode. Conversion must not
relabel real data as simulated demonstration data or vice versa.

The initial repository may include a schema-valid example. Unless explicitly
accompanied by provenance, that example is synthetic and cannot be cited as a
real-robot experiment.

## Record structure

The general versioned trajectory schema can represent these episode-level
fields; not every compact NPZ field is duplicated at episode level:

- schema version and episode ID;
- source (`sim`, `real`, or `real_replay`);
- seed, task class, instruction, and instruction-template ID when known;
- coordinate-frame and unit metadata;
- success/failure outcome and failure reason;
- system, calibration, and randomization metadata;
- ordered step records.

Step-level fields include timestamp, robot state, five-dimensional action,
reward, terminated/truncated flags, and optional image reference. Real-log
extensions can also carry camera timestamps, detections, joint states, EEF
pose, controller status, and calibration identifiers.

The canonical physical action is:

```text
[dx_m, dy_m, dz_m, dyaw_rad, gripper_normalized]
```

It is expressed in `base_link`; the gripper range is `[-1,1]`. Import rejects a
different shape, non-finite values, invalid timestamps, unknown units, or a
missing/incorrect frame unless an explicit calibrated conversion is supplied.

## Storage and media

- The compact simulation dataset stores RGB frames directly in compressed NPZ.
  External-image datasets should use lossless PNG or a documented codec when
  visual artifacts are training-relevant.
- Episode metadata and summaries use UTF-8 JSON/JSONL; metric tables use CSV
  with an explicit header.
- Store image paths relative to the dataset root; do not commit workstation
  absolute paths.
- Keep a manifest with file checksums, schema version, creation command,
  dependency versions, and license/provenance notes.
- Large generated datasets and checkpoints are not source files and should be
  distributed as versioned release assets or through a dataset host.

## Splits and leakage prevention

Split complete episodes before producing training windows. Overlapping action
chunks from one episode remain in one split. Evaluation seeds, OOD layout
regions, and paraphrase templates are excluded from training. A manifest stores
the exact episode IDs in every split.

Class counts, instruction-template counts, source counts, trajectory lengths,
and retained/attempted expert counts should be reported for each split. A
dataset with class or template imbalance must disclose it.

## Preprocessing

Expected preprocessing includes image resizing/scaling, UTF-8 byte
tokenization, optional explicit state normalization, and normalized action
scaling. The current model scales `uint8` RGB internally and otherwise consumes
the environment's raw `float32` state vector. If state normalization is added,
its statistics are computed on the training split only and saved with the
dataset/checkpoint.
Action chunks near episode ends carry a validity mask rather than padded values
being treated as targets.

Augmentation and domain randomization are part of the data-generating process
and must be logged. Semantic markings that define a class should not be
randomized away unless the experiment explicitly studies label ambiguity.

## Quality checks

Before training:

- validate schema version, action shape/order, units, frame, and finite values;
- check timestamps are monotonic within each stream;
- verify referenced images exist and decode;
- inspect state/action range histograms and saturation rates;
- verify no episode ID or image checksum crosses splits;
- summarize success/failure and class balance;
- render a small sample with action and instruction overlays;
- retain rejected-record counts and reasons.

## Real-data privacy and security

Real camera frames can capture people, screens, labels, serial numbers, or
facility details. The importer does not grant permission to publish them.
Before committing or sharing a real log:

- confirm collection consent and organizational authorization;
- remove faces, badges, screens, customer parts, and other sensitive content;
- strip workstation paths, hostnames, IP addresses, credentials, and ROS graph
  details not needed for reproduction;
- document retention and deletion policy;
- scan archives and metadata, not only visible frames.

Robot logs can reveal workspace geometry and control behavior. Treat them as
sensitive operational data where appropriate.

## Licensing

Simulator-generated episodes created solely from this repository's MIT-licensed
assets can be distributed under terms chosen by their creator, subject to the
licenses of any added assets or annotations. Imported logs retain their source
license and usage restrictions. A project code license does not automatically
license third-party images, robot descriptions, pretrained weights, or real
factory recordings.

## Known biases and limitations

- Synthetic labels and visual cues do not represent the diversity of real
  quality defects.
- Privileged expert trajectories are smoother and better localized than many
  real demonstrations.
- Fixed camera and tabletop geometry bias the data toward one cell layout.
- Template-based instructions cover a narrow vocabulary and intent set.
- Successful-only imitation data underrepresents recovery and failure states.
- Domain randomization is bounded by human-selected ranges.

## Maintenance and versioning

Schema changes require a version increment and, when possible, a migration
utility. Never overwrite a published dataset version in place. Corrections
should create a new manifest that records what changed and preserves a pointer
to the affected version.
